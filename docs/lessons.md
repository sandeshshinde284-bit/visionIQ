# Lessons (LRN-10)

Repeated failures become **lessons**: one reusable unit of knowledge supported by several tickets
(master design §6.10, §8.9, §6.20). Run once per schedule:

    PYTHONPATH=src/VisionIQ.Intelligence python -m app.knowledge.lessons_cli

Uses the intelligence database login (`DB_INTELLIGENCE_*`): it reads evidence and writes only the
`knowledge` schema. `LESSON_DEFECT_TYPES` (default `Bug`) lists the work-item types that count as defects.

## Qualification rule

| Rule | Detail |
|---|---|
| Observation | A defect ticket (not deleted) with an **explicit** fix link that a review has not disputed, plus the files that fix **changed** (`evidence.fix_change_sets`), ignoring build/lock/doc noise |
| New lesson | At least **2 distinct tickets** whose fixes changed overlapping files (Jaccard ≥ **0.5**) in the **same repository**. One ticket alone stays an observation. Titles and wording are never compared |
| Join | A new observation overlapping exactly one lesson joins it (no new lesson version) |
| Ambiguous | Overlapping several lessons → `HUMAN_REVIEW` (not joined) |
| Cause | Always `unverified`; only a named human can mark a lesson current or its cause verified (the database enforces this) |
| Revert | A later revert of any supporting fix appends a **disputed** revision; earlier revisions are kept (the database rejects edits and deletions) |

Thresholds and noise patterns are constants in `app/knowledge/lessons.py` (`MIN_TICKETS`, `OVERLAP`, `NOISE`).

## Where things are

| Table | Content |
|---|---|
| `knowledge.lesson_patterns` | One row per lesson and its latest revision number |
| `knowledge.lesson_revisions` | Append-only versions: status (candidate / current / disputed / stale), cause status, title, signature files, supporting observations, decision, rationale, generated by, verified by, OKF path/revision (for a later OKF export) |
| `knowledge.lesson_memberships` | Which observation supports which lesson |
| `knowledge.lesson_observations` | The evidence each observation was built from |
| `knowledge.lesson_decisions` | Every decision with its rationale: CREATE_NEW, LINK_EXISTING, REVISE_EXISTING, HUMAN_REVIEW, WAIT_FOR_EVIDENCE |

Runs are deterministic and idempotent (same evidence, same lessons; a repeated decision is not re-logged)
and serialized with an advisory lock.

Scenario 3: Ticket-Fix Link Lifecycle (LRN-04)

Question: How does a ticket-fix link move from ACTIVE to RETRACTED to ACTIVE again? Which files manage the state?

1. Initial State: ACTIVE
File: PostgresTicketFixLinkStore.cs:UpsertSourceAsync()
→ Link created in ticket_fix_links with retracted_at = NULL
2. Source No Longer Has Link
File: PostgresTicketFixLinkStore.cs:ReconcileSourceAsync()
→ Called when a work item or PR is re-synced with updated links
→ Finds that this link is no longer in the source's claim list
→ Calls: RetractAsync() → ChangeStatusAsync()
3. State: RETRACTED
Database Update: UPDATE ticket_fix_links SET retracted_at = now() WHERE association_key = ?
Table: evidence.ticket_fix_link_lifecycle_events
→ Appends immutable row: (association_key, 'retracted', now())
4. Human Reviews & Decides
(Optional) Operator reviews in UI and marks as "Disputed"
→ Stored separately (never cleared by source updates)
5. Source Reasserts the Link (Later)
File: PostgresTicketFixLinkStore.cs:UpsertSourceAsync()
→ New sync of the work item finds the link again
→ Calls with clearRetraction: true
→ Updates: UPDATE ticket_fix_links SET retracted_at = NULL WHERE association_key = ?
6. Back to ACTIVE
Lifecycle Event: (association_key, 'relinked', now()) appended
Human review (if exists) remains untouched
Next queries see the link as ACTIVE again
